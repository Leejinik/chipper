# Chipper

Markdown · 텍스트 · HTML 문서를 편집하는 가벼운 크로스플랫폼 데스크톱 에디터.
왼쪽에서 소스를 편집하면 오른쪽에 렌더링 결과가 실시간으로 보이는 분할 편집에,
ID 목록을 다루는 **파워툴**(SQL `IN` 절 변환, chips 자동입력)을 더했습니다.

## 에디터

- **여러 문서를 탭으로** 열고 전환 (`.md` `.markdown` `.txt` `.log` `.html` `.htm` 등)
- **분할 화면**: 왼쪽=소스(편집) / 오른쪽=미리보기(읽기 전용). Markdown/HTML 은 분할, 일반 텍스트는 단일 편집
- **CodeMirror 6 기반**: 줄번호·구문 강조·괄호 매칭, 다크 테마
- **멀티 커서**: `Alt`+드래그(컬럼 선택, 드래그 중 Alt 눌러도 됨) · `Ctrl`+`D`(다음 항목 선택) · 모두 찾기 → 전 일치 멀티 커서
- **찾기 / 바꾸기** (`Ctrl`+`F` / `Ctrl`+`H`): 이전/다음·모두 찾기·바꾸기·모두 바꾸기, 대/소문자·단어 단위·정규식
- **우클릭 메뉴**: 실행 취소/다시 실행·잘라내기/복사/붙여넣기·모두 선택·찾기
- **확대/축소**: `Ctrl`+마우스 휠로 **편집기와 미리보기를 함께** 확대/축소, `Ctrl`+`0` 으로 초기화 (탭·버튼 등 UI 크기는 고정)
- **자동 저장 & 세션 복원**: 그냥 창을 닫아도 다음 실행 때 열려 있던 탭·내용이 복원됩니다 (확대 배율·단축키 설정도 유지)
- **파일 열기/저장/드래그드롭**, **인코딩** 감지·변환 (UTF-8 / UTF-8 BOM / CP949(EUC-KR) / UTF-16 LE·BE)

## 파워툴 (블록 선택 시 활성화)

줄바꿈 또는 공백으로 구분된 ID 목록을 선택하면 다음 버튼이 활성화됩니다.

- **`( ) IN절 변환`**: `123 456 789` → `(123, 456, 789)`, 여러 줄이면 줄바꿈을 유지한 `(...)`
- **`⌨ chips 자동입력`** (`Ctrl`+`P`): 선택한 ID 목록을 **외부 웹폼의 chips 입력창**에 한 개씩 자동으로 타이핑 + 확정(Enter/Tab/쉼표). 45개를 손으로 입력하던 걸 대신합니다.
  - 버튼 → **카운트다운(기본 3초, 1~10초 조절)** 동안 대상 입력창 클릭 → 자동 입력. 카운트다운·입력 중 언제든 취소(취소 버튼/Esc), 포커스가 대상 창을 벗어나면 자동 중단
  - Windows(Win32 SendInput) / macOS(osascript, 첫 실행 시 손쉬운 사용·자동화 권한 필요)

## 기본 앱으로 열기 (파일 연결)

탐색기/Finder에서 `.md` `.txt` 등을 **더블클릭하면 Chipper로 열리도록** 설정할 수 있습니다.
Chipper가 이미 실행 중이면 새 창 대신 **기존 창의 새 탭**으로 열립니다.

- **Windows**: 툴바의 `🔗 파일 연결` → 원하는 확장자를 체크하고 **적용**하면 ‘다른 앱으로 열기’ 목록에
  Chipper가 추가됩니다(관리자 권한·설치 불필요, 현재 사용자 계정에만 등록). 이어서 **`기본 앱 설정 열기…`**
  버튼으로 Windows 설정을 열어 형식별 기본 앱을 Chipper로 지정하세요.
  > 최신 Windows는 앱이 기본값을 강제로 바꾸는 것을 막으므로, 마지막 ‘기본 앱’ 지정은 사용자가 직접 확인합니다.
  포터블 exe를 다른 폴더로 옮겨도 다음 실행 때 연결 경로가 자동으로 갱신됩니다.
- **macOS**: `🔗 파일 연결`에 안내가 표시됩니다. Finder에서 파일 선택 → `⌘I`(정보 가져오기) →
  ‘다음으로 열기’에서 Chipper 선택 → **‘모두 변경…’**. (앱 번들 `Info.plist`에 문서 타입이 선언되어 있어
  Chipper가 후보로 나타납니다.)

## 단축키

| 동작 | 키 |
| --- | --- |
| 새 파일 / 열기 / 저장 / 다른 이름으로 | `Ctrl`+`N` / `O` / `S` / `Shift`+`S` |
| 탭 닫기 / 탭 전환 | `Ctrl`+`W` / `Ctrl`+`Tab` |
| 찾기 / 바꾸기 | `Ctrl`+`F` / `Ctrl`+`H` |
| IN절 변환 / chips 자동입력 | `Ctrl`+`I` / `Ctrl`+`P` |
| 다음 항목 선택(멀티 커서) | `Ctrl`+`D` |
| 확대 / 축소 / 초기화 | `Ctrl`+휠 / `Ctrl`+`0` |

> **단축키 재지정**: 툴바의 `⌨ 단축키` 버튼에서 위 **특수 기능**들의 키를 원하는 조합으로 바꿀 수 있습니다(설정은 저장·복원). 복사·붙여넣기·실행취소 같은 표준 편집 키와 `Ctrl`+`Tab` 탭 이동은 고정입니다.

## 실행 / 빌드

```powershell
wails dev     # 개발 모드 (핫 리로드)
wails build   # 배포용 실행 파일 → build\bin\chipper.exe
```

### 리눅스 (Ubuntu 24.04 / 26.04)

```bash
sudo apt install -y build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev
wails build -tags webkit2_41    # → build/bin/chipper
wails dev   -tags webkit2_41
```

`-tags webkit2_41`은 **필수**입니다. Ubuntu가 24.04에서 `webkit2gtk-4.0`을 제거했는데 Wails v2는
아직 pkg-config를 4.0으로 가리키고 있어, 태그 없이는 `webkit2gtk-4.0.pc not found`로 실패합니다.

실행 측에는 `libwebkit2gtk-4.1-0`, `libgtk-3-0t64`, `libsoup-3.0-0`이 필요하며 Ubuntu 24.04+
데스크톱에는 이미 있습니다(서버/최소설치라면 `sudo apt install libwebkit2gtk-4.1-0`). 한글
편집이 주 용도이므로 `fonts-noto-cjk`도 함께 설치하세요. 툴바 라벨이 이모지를 쓰므로
`fonts-noto-color-emoji`가 없으면 ▯로 보입니다(데스크톱 설치에는 기본 포함).

릴리즈 리눅스 바이너리(`chipper-linux-amd64`)는 CI가 **ubuntu-24.04**에서 빌드합니다. 실행
범위를 정하는 관문이 둘이고 더 빡빡한 쪽이 이깁니다 — glibc 2.34(→22.04+)와
`libwebkit2gtk-4.1.so.0`(24.04는 기본, **22.04는 별도 설치 필요**). 22.04에도 SRU 백포트로
`libwebkit2gtk-4.1-0`(2.50.x)이 있어 실행은 되지만 기본은 4.0 계열이고 GTK 패키지명도
`libgtk-3-0`입니다.

**리눅스에서 빠지는 기능이 두 가지 있습니다.** ① **파일 연결/기본 앱 지정**은 Windows 레지스트리
(HKCU) 기반이라 리눅스 빌드에서는 `🔗 파일 연결` 패널 자체가 숨겨집니다 — 대신 데스크톱 환경의
"다른 프로그램으로 열기 → 기본으로 사용"을 쓰세요. ② **ID 자동 입력(autotype)**은 Win32 키 입력
합성에 의존하므로 리눅스에서는 "이 플랫폼에서는 자동 입력이 지원되지 않습니다"를 반환합니다.
편집기·파워툴 등 나머지 기능은 모두 동일하게 동작합니다.

Wails 특성상 **각 플랫폼 바이너리는 그 플랫폼에서** 빌드해야 합니다 (Windows는 Windows에서,
리눅스는 리눅스에서, macOS `.app`은 macOS에서). 리눅스/macOS 백엔드가 cgo로 시스템 웹뷰를
링크하기 때문입니다.

## 개발 메모

### 세션 파일 형식을 바꾸면 파일 이름도 바꾼다

자동 저장 세션은 `~/.chipper/session.v3.json` 에 있습니다(형식 3). v1.1 은 형식 2 를 `session.json`
에 쓰면서, 모르는 형식(3)을 만나면 자기 환영 문서로 덮어썼습니다. 그래서 v1.2.1 부터는 형식마다
**다른 파일**을 씁니다.

- 세션 형식(`SESSION_VERSION`, Go `sessionFormatVersion`)을 올리면 **파일 이름도 같이 바꿉니다**
  (`session.v4.json` …). 같은 파일에 새 형식을 쓰면, 그 파일을 여는 옛 판이 「모르는 형식」으로
  처리하게 됩니다.
- 새 판은 처음 켤 때 자기 파일이 없으면 직전 형식 파일을 **읽기만** 해서 시작점으로 삼고, 옛 파일은
  절대 쓰지 않습니다(`loadLegacyStart`). 옛 파일이 자기 파일보다 새로우면(옛 판에서 작업함)
  안내 막대에 「예전 버전 작업 불러오기」를 띄웁니다.
- 반대로 옛 판이 더 새 형식의 세션을 만나면 깨진 것으로 옮기지 않고 그대로 두며, 그 실행은 세션을
  쓰지 않습니다(v1.2.1 의 `checkSession` → `newer`).
